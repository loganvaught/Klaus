# Klaus
Klaus is a wireless, vibration-based metronome designed for ensembles that struggle to hear traditional metronomes in loud rehearsal environments. It uses an STM32F411, NRF24L01+, and a DRV2605L-driven LRA to generate precise, synchronized vibrations across multiple devices.
## Features
- Linear resonant actuator (LRA) for strong click sensations
- Adjustable tempo via rotary encoder
- Wireless syncing with multiple devices using custom RF protocol
- Rechargeable li-ion battery with informal testing of 24+ hour battery runtime

## Results and Feedback
- Tested with real ensembles to help guide the engineering process
- Very useful for large setups / rehearsals with rhythmically complex pieces
- Vibrations generated by ELV1411A are quite weak; first-time users may struggle to feel pulse
- Latency between devices is imperceptible during extended use
- Greatly improves ensemble comfort with long periods of silence

## Peripherals / Functionality
- I2C: DRV2605L
- SPI: NRF24L01+
- UART: Serial debugging
- Timers: RF syncing and metronome beat generation, microsecond delay for driver setup / mode switching
- GPIO Interrupts: rotary encoder for tempo change, RF interrupt detection
## Project Challenges
- Designing a synchronization method that accounts for clock drifting and dropped packets
- Implementing datasheet state machine logic, calibration procedures, and error detection
- Maintaining a steady power supply for STM32F411 and NRF24L01 + PA + LNA
## Design Choices / Tradeoffs
- LRAs generate stronger "click" sensations for musicians
- PA + LNA version of the NRF enhances reliability in larger setups
- Disabled auto-ack/retransmit to avoid RF collisions with multiple receivers
- RF uses a single pipe for simplicity; only one is required for this project
- DRV2605L driver designed for setup with ELV1411A. Tradeoff for simplicity because of time constraints
- AP2112K-3.3 has a high max current for supplying the PA + LNA demands. An adapter board might be easier to use
## Future Improvements
- Needs a stronger LRA than the ELV1411A
- DRV2605L driver should have user supplied waveform library and calibration values to support multiple haptic devices
- An RF protocol that uses two-way communication would be more precise. Would need to avoid air collisions
- Custom PCBs would make assembling much easier and allow for a smaller enclosure
## How to Make
- Clone the repo, and open the Klaus container folder (inside this repo) in STM32CubeIDE
- Use an ST-Link (or other method) to flash the STM32F411CEU6
- View pin mapping by opening .ioc file in STM32CubeMX
- View block diagram below for help putting device together. (Note: diagram does not show rotary encoder or mode-switching button)
- Supply 5v to the STM32 5v pin, and the DRV2605L haptic board. Supply 3.3v to the NRF24L01+ board; or, use an NRF24L01 adapter board, which takes 5V.
